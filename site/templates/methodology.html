Methodology

A forecast designed to be revised

Construction cash flow depends on information that changes throughout a project: activity timing, progress, certification, payment timing, subcontracting, variations and commercial decisions.

CashflowPot therefore does not try to create a permanently precise prediction. It creates a transparent forecast from the information available now, using a repeatable model that can be recalculated quickly when reality changes. When the forecast will need to change anyway, updating it should take minutes, not weeks.

Contractor point of view

  1. Build activity work curves
  2. Convert combined work into client-side contract value
  3. Apply client billing and payment conditions to create inflow
  4. Apply activity and subcontract conditions to create outflow
  5. Combine inflow and outflow to calculate net cash and financing

The basic principle

Work happens first. Cash timing comes second.

CashflowPot separates the physical/economic progress of the project from the commercial conditions that determine when money is actually received or paid.

First, each activity produces a value-of-work pattern over time. Then the relevant contract, billing and payment assumptions transform that work into cash.

Main contract · contractor point of view

Contract side — from work to inflow

1. Build the project work curve

Each activity is calculated as either a linear work distribution or a skewed S-curve. The activity work curves are then summed to create the project cost-loaded work curve.

Project cost work(t)

Project cost work(t) = Σ Activity work(t)

2. Convert cost-loaded work to contract-value work

The current model uses the same contract-value-to-cost factor across all entered activities.

Value factor = Contract value / Total entered activity cost

Contract-value work(t) = Project cost work(t) × Value factor

This means CashflowPot does not currently store a separate selling value for each activity. The contract value is distributed proportionally to entered activity cost.

Second pass

Turn contract-value work into cash receipts

The contract-value work curve represents work executed. It is not yet the cash-in curve. CashflowPot then applies the client-side commercial assumptions that affect billing, certification and payment timing.

  • Client advance payment and proportional recovery
  • Work in Excess of Billings (WIEB) assumption (%)
  • Retention withheld from progress receipts
  • Payment period between billing and receipt
  • Retention released at completion
  • Remaining retention released after the Defects Liability Period (DLP)

Billing reality

Work in Excess of Billings (WIEB) assumption (%)

In practice, not all work performed in a period is immediately billable. Work may still be incomplete, awaiting inspection or approval, affected by an NCR, or otherwise not ready for certification.

CashflowPot uses a percentage assumption to estimate the share of work performed in a period that is not yet billable and is carried into the following billing period.

Example — WIEB assumption 20%

If 100 of otherwise billable work is performed in the current period, 80 is billed in the current period and 20 is carried into the next billing period.

Billed(t) = Work(t) × (1 − WIEB) + Work(t−1) × WIEB

The percentage is a forecasting assumption used to simulate WIEB. The actual WIEB is the resulting value of performed work that remains unbilled.

Project execution · contractor point of view

Execution side — from activity work to outflow

1. Calculate each activity work curve

An activity can use a linear distribution or a skewed S-curve depending on how that work is expected to progress. A general-requirements activity may be broadly linear; trade activities often ramp up and down and are better represented by a curved distribution.

Linear cumulative work(t) = Activity cost / Duration × t

For non-linear activities, the skew parameter changes whether work is relatively front-loaded, balanced or back-loaded.

2. Split execution cost by procurement route

Each period's activity work is divided into self-performed/direct cost and subcontracted cost.

Self-performed cost(t) = Activity work(t) × (1 − Subcontracted share)

Subcontracted work(t) = Activity work(t) × Subcontracted share

Two cost patterns

Self-performed and subcontracted work behave differently

Self-performed / direct cost

Self-performed work is not adjusted by WIEB. Even if the related work cannot yet be billed or certified to the client, the labour, plant, materials and other direct cost is generally incurred when the work is performed.

The current model therefore records the non-subcontracted share in the same period as activity work.

Subcontracted share

The subcontracted portion follows its own commercial relationship. Its executed work can be transformed into cash payments using subcontract-specific advance, WIEB, no-billing period, retention, payment delay and DLP assumptions.

Project outflow = Σ Activity outflow

Core terminology

The assumptions that move work into cash

Advance payment

An amount paid at the beginning of the relevant relationship and recovered proportionally from later progress payments.

Retention

A percentage withheld from progress payments and released later. CashflowPot models a first release at completion and the remaining release after the DLP.

Payment period

The number of model periods between billing and actual receipt or payment.

Defects Liability Period (DLP)

The number of model periods between the first retention release and release of the remaining retention.

No-billing period

An initial subcontract period in which work may occur but no progress bill is issued. The accumulated work is included in the first bill after that period.

Pre-work period

An initial period before an activity's main cost-loaded work begins. The current backend retains a legacy mobilization-period field for this behavior.

Subcontracted share

The fraction of an activity cost that follows subcontract billing and payment assumptions. The remainder is treated as self-performed/direct cost.

Curve skew

Controls the timing shape of a non-linear activity. Positive skew front-loads the current curve relative to the balanced case; negative skew back-loads it.

Bring the two sides together

Net cash and financing

Once project inflow and project outflow exist for each period, CashflowPot calculates the net position and carries that balance through time.

Net cash flow = Inflow − Outflow

Pre-finance balance(t) = Previous balance + Net cash flow(t)

If the balance is negative, the current engine applies the financing rate for that model period:

Balance(t) = Pre-finance balance(t) × (1 + financing rate)

If the balance is positive, the current model does not add interest income.

Time convention

The engine works in periods

CashflowPot normally uses monthly periods, but the calculation engine itself works in integer periods. Timing assumptions within one scenario must use the same unit.

A payment period of 2 means the related progress amount is shifted by exactly two model periods. A DLP of 12 means the remaining retention is released twelve periods after the first retention-release point. The financing rate is also a rate per model period.

Planned model extension

Activity-specific selling value and markup allocation

Today, CashflowPot uses the same contract-value-to-cost factor across activities. That is deliberately simple, but it does not represent a contractor's ability to distribute markup differently across the Schedule of Values.

Activity-specific selling value and markup allocation is a planned extension. It will allow the inflow model to reflect where contract value and margin are actually placed—for example, allocating a higher markup to earlier activities to improve the early cash position—while keeping the overall contract value controlled.

Model checks

Key invariants

Commercial terms change the timing of cash. For valid inputs, they should not create or destroy the underlying activity cost or contract value.

Σ Activity work = Activity estimated cost

Σ Activity outflow = Activity estimated cost

Σ Project inflow = Contract value

Advanced detail

Activity curve formula

Most users only need to choose linear or a skewed activity curve. The calculation engine also corrects the non-linear curve so that total marginal work returns to the activity's estimated cost.

Show the non-linear curve formula

The raw cumulative non-linear curve is:

C_raw(t) = c × (s + 1) / ((s + 1) + exp(−(t / (0.1d) + s² − 5)))

The engine calculates the residual between the resulting marginal work and activity cost, then applies a cubic cumulative correction over the duration before differencing the curve again.

error_distribution(t) = −2 × error × t³ / d³ + 3 × error × t² / d²

Use the forecast for what it is

Assumptions and limitations

CashflowPot produces a forecast, not a guarantee. Its usefulness depends on the quality and currency of the assumptions supplied.

  • The current model allocates contract value proportionally to activity cost.
  • It is activity-based rather than labour-, plant-, material- or quantity-resource loaded.
  • It is not Primavera P6, MS Project, ERP, accounting software or contractual certification software.
  • It does not perform delay or entitlement analysis.
  • The current financing model applies a per-period rate only while the cumulative balance is negative.

The goal is not to pretend uncertainty can be removed. The goal is to use the information currently in hand, make the assumptions visible, and make the forecast fast enough to revise when the project changes.
